Here is the complete CRUD operation workflow for all 5 members:

MODULE 1 — Tutor Profile & Availability (Member 1)
The workflow begins when a student decides they want to become a tutor on the platform. They fill in their registration form with their name, student ID, subjects they are good at, a short bio, and their hourly rate. This is the CREATE operation — a new tutor profile record is saved to the database with a status of "Pending Verification". Once admin approves, the status changes to "Active".
Next, the tutor sets up their availability calendar. For each available time slot they add, the system CREATEs a new availability record with the date, start time, end time, and a status of "Free". Other students can then READ this calendar when browsing for tutors — they see which slots are free and which are already booked.
When the tutor wants to change their bio, update their subjects, or adjust their hourly rate, that is an UPDATE on the profile record. When the tutor wants to remove an available time slot they no longer want, that is a DELETE on that specific availability record. If a tutor decides to leave the platform entirely, their profile is soft-deleted — hidden from search results but kept in the database so past session records remain intact.

MODULE 2 — Session Booking & Scheduling (Member 2)
The workflow starts when a student browses the platform and finds a tutor they like. They select a subject, choose an available time slot from the tutor's calendar, and submit a booking request. This CREATEs a new booking record with: studentId, tutorId, subject, date, startTime, endTime, status = "Pending", and a generated bookingId.
The tutor receives a notification and reviews the request. If they accept, the system UPDATEs the booking status from "Pending" to "Confirmed". At the same time, that time slot in Module 1's availability calendar is UPDATEd from "Free" to "Booked" so no one else can book the same slot.
The student can READ all their bookings from their booking history dashboard — upcoming sessions, past sessions, and cancelled ones. The tutor can also READ their full schedule showing all confirmed bookings.
If the student needs to cancel, the system UPDATEs the status to "Cancelled" — but only if it is more than 2 hours before the session starts, which is a business rule. The cancelled slot in the availability calendar is then UPDATEd back to "Free" so other students can book it. A booking record is never hard-deleted — it stays in the database for history and reporting purposes.

MODULE 3 — Real-time Chat & Resource Sharing (Member 3 — Your Part)
The workflow activates the moment a booking is confirmed by Module 2. A private chat room is automatically created and linked to that sessionId. Both the student and tutor now have access to four features.
For In-Session Messages — when the session is active, the student asks a question via the chat window. This CREATEs a message record with sessionId, senderId, messageText, sentAt, and messageType = "in_session". The message is delivered instantly via SignalR to the tutor. The tutor READs it in real-time and replies, which CREATEs another message. If either person made a typo, they can UPDATE their message within 5 minutes. If they want to remove a message, it is a soft DELETE — hidden from the UI but kept in the database.
For Out-Session Messages — after the session ends, the student goes home and gets stuck on their homework. They open the platform and send a follow-up question. This CREATEs a message with messageType = "out_session". The tutor sees a notification badge and READs it when they are available, then replies. The sender can UPDATE their message within 30 minutes and soft DELETE their own message anytime.
For Files and Resources — the tutor uploads a PDF practice sheet. This CREATEs a file record and stores the actual file on the server. The student READs the materials library and downloads it. The tutor can UPDATE the file name if needed and DELETE the file if it was uploaded by mistake.
For Session Notes — after the session ends, the tutor opens the notes form and CREATEs a structured summary with topics covered, homework assigned, and next steps. The student logs in the next day and READs the note from their dashboard. The tutor realizes they forgot something and UPDATEs the note within 24 hours. Only an admin can DELETE a session note.

MODULE 4 — Rating & Analytics Dashboard (Leader)
The workflow begins after a session is marked "Completed" by the booking system. The student receives a prompt asking them to rate their session. They select a star rating from 1 to 5 and write a review. This CREATEs a rating record with sessionId, studentId, tutorId, stars, reviewText, and submittedAt. Business rule: a student can only rate a session once, and only after it is marked Completed.
The tutor's average rating on their public profile is then automatically recalculated — this is an UPDATE to the tutor's profile aggregate score. Other students browsing for tutors can READ this average rating and individual reviews on the tutor's profile page.
If the student made a spelling mistake in their review, they can UPDATE it within 1 hour of submission. After that the review is locked. If a review contains inappropriate language, the admin can DELETE it — soft delete with the reason logged.
For the analytics side, the tutor can READ their own dashboard which shows total sessions completed, total earnings, average rating over time, and which subjects are most popular. The student can READ their own dashboard showing total sessions attended, money spent, and their most frequently booked tutors. The admin can READ a platform-wide analytics panel showing all activity across all users.

MODULE 5 — Session Recording & Moderation (Member 5)
The workflow starts after a session is marked "Completed". The tutor opens the upload page and selects the recording file from their device. This CREATEs a recording record with sessionId, tutorId, fileName, fileSize, uploadedAt, and status = "Active". The actual video or audio file is stored on the server. Business rule: only the tutor who conducted that specific session can upload its recording, and only after the session status is "Completed". File size limit is 100 MB.
The student logs in and opens their session history. They can READ a list of all recordings available for their sessions and click to play them back directly in the browser. Business rule: students can only access recordings from their own sessions — they cannot see recordings from any other student's session.
If the tutor uploaded the wrong file or the wrong session's recording, they can DELETE it and re-upload the correct one. This removes the file from the server and updates the database record status to "Deleted".
The admin opens the moderation dashboard and can READ all recordings across the platform. If a recording contains inappropriate content, the admin UPDATEs its status to "Flagged" and it is immediately hidden from the student. After reviewing, the admin can either restore it by UPDATEing the status back to "Active", or permanently DELETE it with a moderation reason logged. The platform also runs an automated process that DELETEs recordings older than 30 days to manage storage.

How All 5 Modules Connect — The Full Workflow
A student visits the platform. Member 1's module lets them browse tutor profiles and availability. They find a tutor and Member 2's module handles the booking — confirming the session and locking the time slot. Once confirmed, Member 3's module opens the chat room so they can communicate, share files, and exchange messages before, during, and after the session. When the session ends and is marked Completed, Member 4's module prompts the student to leave a rating and shows both parties their analytics. Meanwhile Member 5's module allows the tutor to upload the session recording so the student can review the lesson anytime within 30 days.
Each module hands off to the next. No module works in isolation. Together they form one complete, connected tutoring platform.
